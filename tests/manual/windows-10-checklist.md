# Windows 10 发布验收清单

每次验收创建独立证据记录；不得把 Windows 11 结果混入本表。安装器基准为 `DeskButler-Setup-0.1.0.exe`；文件大小和 SHA-256 必须抄录本轮 `scripts\verify-release.cmd` 的最终输出并在验收前重新计算，不得沿用旧产物数字。

## 环境证据

- [ ] 记录日期、执行人、机器/VM 标识、Windows edition、版本及完整 OS build。
- [ ] 记录 x64、当前用户名是否为专用测试账户、DeskButler fixture/安装器版本。
- [ ] 记录每台显示器设备名、主屏、分辨率、工作区坐标（含负坐标）、缩放/DPI 与排列图。
- [ ] 记录本轮安装器文件大小 `64,593,555` 字节、SHA-256 `208C7C4C9752A711B126529CBBB484ACF7E3B04ED2E066479CCB448E072A295E`；重新计算并确认一致。
- [ ] 运行 `verify-clean-account-prerequisites.ps1 -ExpectedTestAccount <专用账户>`；必须为 `READY`，不得绕过 `BLOCK`。
- [ ] 确认 QQ、微信、富途均为专用 VM 中的测试安装与测试账号；记录各自主程序版本、启动入口完整路径和初始 PID。

## 安装、现场与登录卡

- [ ] 当前用户安装不触发管理员提升；开始菜单、卸载项与 HKCU Run 精确出现。
- [ ] 打开两个 `DeskButler.TestWindow` fixture 和一个唯一临时 Explorer 目录，记录 fixture build/hash、PID、HWND、路径和初始物理像素矩形。
- [ ] 等待并确认快照生成；最近有效快照始终仅 3 份。
- [ ] 重新登录后恢复卡出现；完整等待 15 秒，确认只收起且绝不自动恢复。
- [ ] 从管家主界面手动调用恢复；缺失 fixture 返回，窗口四边相对 DPI 期望误差均不超过 8 物理像素。
- [ ] 对恢复计划执行取消；后续项目停止，已启动窗口不被关闭或回滚。
- [ ] 键盘可聚焦卡片、详情、恢复、跳过、取消；Tab 顺序可预测，Enter/Space 行为正确，焦点可见。
- [ ] 导出脱敏诊断包，记录 bundle id、包含类别和导出文件 SHA-256；若界面仍无导出入口，记录 `BLOCK`，不得用预览代替。

## 常驻应用发现与确认

- [ ] 启动 QQ、微信、富途并分别缩到通知区域；记录缩托盘前后 PID 与主程序完整路径，确认进程仍在。
- [ ] 等待后台自动捕获，确认它不会自行弹出候选或写入常驻列表。
- [ ] 从托盘点“保存当前现场”或首页点“立即保存现场”，确认首页出现“发现的常驻应用”。
- [ ] 对 QQ、微信、富途分别记录候选显示名、可信度、默认勾选状态和候选启动路径；高可信新应用默认勾选，低可信默认不选，helper/updater 不得被当作无需确认的主入口。
- [ ] 若候选指向 helper 或入口不明确，用“浏览修正”选择真实主程序；确认添加前记录最终选择，未选项不得写入设置。
- [ ] 打开“设置”页，确认三项进入常驻列表；逐项验证显示名、路径状态、启停、上移、下移、替换路径和删除操作可用。
- [ ] 将启动顺序固定为 QQ → 微信 → 富途，并记录设置前后顺序；关闭再打开 DeskButler，确认顺序和总开关持久化。

## 常驻登录批次与去重

- [ ] 到真实重启步骤前再次停下，向用户说明将影响当前 VM，并取得**本次、当下、明确**的重启确认；旧确认不得复用。只能由用户手动重启，代理不得调用重启、注销或关机命令。
- [ ] 登录后记录 DeskButler、QQ、微信、富途的进程创建时间及 `resident-launch` 诊断，确认只处理一批且 QQ → 微信 → 富途的尝试顺序不变。
- [ ] 保持三者运行，点“立即启动常驻应用”，确认 `KnownProcessPaths` 去重生效：三个产品都不出现第二实例；记录点击前后 PID 集合。
- [ ] 用微信自身“退出”主动关闭微信，确认进程消失；只退出并重新启动 DeskButler，不重启、不注销 Windows，等待超过自动初始延迟，确认微信没有被再次拉起。
- [ ] 在同一 Windows 登录会话点“立即启动常驻应用”，确认微信可由显式操作重新启动，而仍运行的 QQ、富途不产生重复实例。
- [ ] 修改三项启停、顺序或路径并重启 DeskButler，确认同一登录会话不会建立第二个自动批次；记录修改仅在下次 Windows 登录自动生效。
- [ ] 若需要再次重启验证新设置，必须在实际重启前重新取得一次即时确认；不得把前一次确认视为授权。

## 安装器生命周期与第三方边界

- [ ] 0.1.0 覆盖升级到严格更高 fixture 版本；设置、3 份快照、排除项、常驻列表和 `resident-launch-session.json` 保留。
- [ ] 运行中升级由受控管道自然退出 DeskButler，不按名称杀进程；升级后可重新启动。
- [ ] 保持 QQ、微信、富途运行并记录 PID；静默卸载默认保留整个 `%LOCALAPPDATA%\DeskButler`，包括 `settings.json` 和 `resident-launch-session.json`。程序、快捷方式、卸载项和 DeskButler Run 值清除，无关 Run 值保留，三款第三方应用 PID 均仍在。
- [ ] 重装后交互卸载只询问一次；分别验证“保留”和“删除全部数据”选择。
- [ ] 删除模式只在干净专用账户执行；确认精确 `%LOCALAPPDATA%\DeskButler` 数据根（含常驻设置、会话、快照、日志、故障证据）清除且不影响任何其他路径。
- [ ] 删除模式卸载前后再次记录 QQ、微信、富途 PID；确认卸载不终止三者，不删除或修改三者的 Run 值、计划任务或服务。

## 资源与结论

- [ ] 设置 `DESKBUTLER_RUN_LONG_E2E=1` 和仓库外 `DESKBUTLER_EVIDENCE_DIRECTORY`，在包含常驻列表的构建上实际运行完整 30 分钟，禁止加速冒充。
- [ ] 附每分钟 CSV/JSON：private bytes、handle count、SQLite 主文件/WAL/SHM；最后 5 次句柄不得严格单调增长，有效快照恰为 3。
- [ ] 记录每项 PASS/FAIL/BLOCK、问题链接、诊断 bundle id；只有全部发布门槛 PASS 才签署 Windows 10 基线。
