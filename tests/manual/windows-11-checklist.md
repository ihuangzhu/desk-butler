## 常驻应用发现与确认（Windows 11 独立证据）

- [ ] 在专用 VM 安装测试版 QQ、微信、富途，记录版本、主程序完整路径和 PID；分别缩到通知区域并确认进程仍在。
- [ ] 等待后台自动捕获，确认它不会自行弹出候选或写入列表；随后主动“保存当前现场”，确认首页出现候选。
- [ ] 分别记录 QQ、微信、富途的显示名、可信度、默认勾选和候选路径；高可信新应用默认勾选，低可信默认不选，helper/updater 不得被当作无需确认的主入口。
- [ ] 对主入口不明确或误指 helper 的候选点“浏览修正”，只确认真实主程序；未选候选不得进入设置。
- [ ] 在“设置”页独立验证查找、浏览添加、总开关、逐项启停、上移、下移、替换路径和删除。
- [ ] 将顺序设为 QQ → 微信 → 富途，重开 DeskButler 验证设置持久化；记录 Windows 11 截图和设置文件证据，不能引用 Windows 10 记录。

## 常驻登录批次、去重与主动退出

- [ ] 到真实重启前停下，说明影响并取得**本次、当下、明确**的用户确认；旧确认或 Windows 10 的确认不得复用。只能由用户手动重启，代理不得调用重启、注销或关机命令。
- [ ] 登录后记录 DeskButler、QQ、微信、富途的进程创建时间与 `resident-launch` 诊断，确认只处理一批，尝试顺序为 QQ → 微信 → 富途。
- [ ] 三者运行时点“立即启动常驻应用”，以点击前后 PID 集合证明 `KnownProcessPaths` 去重，不得出现第二实例。
- [ ] 用微信自身“退出”关闭微信；只重启 DeskButler、不重启或注销 Windows，等待超过自动初始延迟，确认微信不被拉起。
- [ ] 同一 Windows 登录会话内点“立即启动常驻应用”，确认微信可手动拉起，仍运行的 QQ 和富途不重复。
- [ ] 修改启停、顺序或路径后只重启 DeskButler，确认同一登录会话没有第二自动批；修改从下次 Windows 登录自动生效。
- [ ] 若需要第二次真实重启，必须临近执行时重新取得即时确认。

## 安装器与第三方安全边界

- [ ] 在干净专用账户验证安装、严格更高版本覆盖升级、默认保留卸载、重装和交互删除卸载；无关 HKCU Run 值不变。
- [ ] 默认静默卸载保留整个 `%LOCALAPPDATA%\DeskButler`，包括 `settings.json` 与 `resident-launch-session.json`；显式删除只清除该精确数据根。
- [ ] 两种卸载前后都记录 QQ、微信、富途 PID，确认三者未被终止；同时证明安装器未改动三者的 Run 值、计划任务或服务。
