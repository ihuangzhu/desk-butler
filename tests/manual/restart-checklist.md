# 真实重启恢复验收清单

此流程包含真实重启。自动化测试和开发代理必须停在“立即重启”之前；**每一次**真实重启都只能在临近执行时取得用户对本次操作的明确确认后，由用户手动执行。确认不能预先取得、跨次复用或从旧任务推断。不得调用 `shutdown`、`Restart-Computer`、注销或等价命令。

## 重启前准备

- [ ] 记录 OS edition/version/build、DPI、显示器布局、测试账户、当前时间。
- [ ] 记录安装器文件名、版本、大小 `64,575,904` 字节和 SHA-256 `E754E70172A07AF74C37683C38773E390D62BD8577F1085BA4403E0221D4B2AB`；记录 DeskButler 与 TestWindow fixture 版本/hash。
- [ ] 确认在专用测试账户；运行 clean-account 门禁及安装/升级链，没有任何 `BLOCK`。
- [ ] 打开两个受控 TestWindow 和唯一临时 Explorer 目录；记录 PID、HWND、路径及物理像素矩形。
- [ ] 等待快照，记录 snapshot id/时间；确认数据库仅 3 份有效快照。
- [ ] 确认登录自启动启用、`run.lock` 正常、诊断目录可写。
- [ ] 在专用 VM 启动 QQ、微信、富途并缩到托盘，通过主动保存确认候选；在设置页核对三项均启用，顺序固定为 QQ → 微信 → 富途，路径状态可用。
- [ ] 记录当前 `resident-launch-session.json` 是否存在、当前三款应用 PID 和进程创建时间；不要编辑或删除会话文件。
- [ ] 保存所有其他工作，关闭与验收无关的个人应用。
- [ ] 到达此行后状态记为 `NEEDS_USER_CONFIRMATION`，说明本次重启的目标和影响，等待用户当下明确确认；未收到确认即停止。
- [ ] **立即重启（仅用户手动执行）**。

## 登录后验证

- [ ] 记录登录时间；确认 DeskButler 单实例自启动且未出现崩溃循环。
- [ ] 记录 QQ、微信、富途进程创建时间与 `resident-launch` 诊断，确认只自动处理一批且尝试顺序为 QQ → 微信 → 富途。
- [ ] 三者运行时点“立即启动常驻应用”，记录点击前后 PID 集合，确认 `KnownProcessPaths` 去重且没有第二实例。
- [ ] 用微信自身“退出”关闭微信；只退出并重启 DeskButler、不重启或注销 Windows，确认同一登录会话不会自动拉起微信。
- [ ] 点“立即启动常驻应用”，确认这是同一登录会话内可手动拉起微信的显式例外，同时 QQ 和富途不重复。
- [ ] 恢复卡出现；不操作并完整等待 15 秒，确认卡片收起且没有自动启动或移动任何窗口。
- [ ] 打开管家，确认刚才 snapshot 仍在最近 3 次中；从主界面手动选择恢复。
- [ ] 确认两个缺失 TestWindow 与唯一 Explorer 目录返回，窗口相对记录/DPI 的四边误差均不超过 8 物理像素。
- [ ] 再执行一轮并中途取消；确认后续动作停止、已启动窗口不被关闭。
- [ ] 仅关闭记录的 fixture PID/HWND，并删除唯一临时目录；不得按名称关闭其他进程或 Explorer。
- [ ] 导出脱敏诊断包，记录 bundle id、文件 SHA-256、恢复结果和任何 FAIL/BLOCK。
- [ ] 若任何 FAIL 需要再次真实重启复测，回到重启前准备并重新取得一次即时明确确认；本轮确认到此失效。
