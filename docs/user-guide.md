# DeskButler 用户指南

本指南对应 0.1.0 本地 release candidate。当前功能是“补充并整理”工作现场，不是休眠，也不能恢复程序内存或未保存内容。

## 安装、打开和退出

运行安装器后，从开始菜单打开 DeskButler。它默认在当前 Windows 用户登录时启动，平时常驻任务栏通知区域，不主动打开主窗口。

- 双击托盘图标：打开主窗口。
- 托盘“打开管家”：打开主窗口。
- 托盘“退出”：停止记录并退出。直接关闭主窗口只隐藏窗口，不等于退出。

“设置”页提供键盘可操作的登录启动开关。切换会同时维护 `settings.json` 与 DeskButler 自己的 HKCU Run 值；任一步失败都会独立尝试恢复两处状态，并重新读取设置、核对实际注册状态。能够核实时，开关显示核实后的真实值；无法证明两处一致时，开关会禁用并提示“无法核实实际状态”，重新启动 DeskButler 后会再次核实。该过程不会修改其他程序的启动项。

## 保存和暂停

托盘选择“保存当前现场”，或主窗口“首页”选择“立即保存现场”。自动记录开启时，窗口变化停止约 10 秒后合并保存；持续变化满约 60 秒会尽力建立检查点。

“暂停捕获”会停止后续自动记录；按钮和托盘文案随后变为“继续捕获”。暂停状态会保存在本机设置中。最近只保留 3 份有效快照，新快照完整生效后才裁剪最旧一份。

快照记录窗口外部状态，不记录程序内部文档内容。保存前请仍然使用各程序自己的保存功能。

## 发现并确认常驻应用

常驻候选不会因后台自动保存而突然写入设置：只有你从托盘选择“保存当前现场”、在首页点“立即保存现场”，或在“设置”页主动点“查找常驻应用”时才进行本轮发现。主动保存成功后若发现候选，主窗口会打开到首页的“发现的常驻应用”；没有候选也不会改动常驻列表。

- 高可信的新应用且已有明确主程序路径时默认勾选；低可信候选默认不选，并显示“低可信，默认不添加”。
- helper、updater、crash reporter 或主入口不明确的候选可能低可信或要求选择主程序 `.exe`；请取消勾选，或先点“浏览修正”确认真实主程序。
- 自动更新后发现可能的新路径时，即使是高可信也不会默认替换；核对旧、新路径后手动勾选并确认。
- 点“确认添加”只保存当前明确选中且路径非空的项；点“本次忽略”不会写入这些候选。

## 管理和启动常驻应用

“设置”页的“常驻应用”区可以切换总开关、查找或浏览添加应用，并对每项执行启用、停用、上移、下移、替换路径和删除。顺序就是下次登录自动处理顺序。路径状态显示“启动路径不存在”或“启动路径无法访问”时，先用“替换路径”选择当前用户可访问的真实主程序；无效路径不能重新启用。

每个 Windows 登录会话只自动处理一批：DeskButler 启动约 5 秒后按已保存顺序处理启用项，项目间至少间隔约 1 秒。处理前会用该产品的全部 `KnownProcessPaths` 判断是否已有进程，已有或无法可靠核实时都不会再启动。每项在越过外部启动边界前先记为已尝试；因此你主动退出某个应用后，仅重启 DeskButler 不会在同一登录会话内再次把它拉起，也没有崩溃守护或持续监控。

总开关、启停、增删、改序和路径修改会立即保存，但自动批次的计划在本次 Windows 登录首次建立后固定；这些设置修改从**下次 Windows 登录**起自动生效。若确实要在当前登录立即应用，可点“立即启动常驻应用”（主窗口设置页和托盘都有入口）：这是显式用户操作，不受本登录自动批次或总开关限制，但只处理逐项仍为“启用”的条目，并仍会检查 `KnownProcessPaths` 避免重复实例。

## 从历史恢复

打开托盘“最近现场”，或进入主窗口“现场”页。列表按最新优先显示最多 3 份；选中一份并点“恢复”。历史入口是手动恢复，即使登录卡片已经隐藏也可使用。

主窗口的历史“恢复”会恢复该快照全部项目，并使用普通恢复策略。当前历史页不先展示逐项计划；需要逐项取消或永久排除时，应使用恢复卡。

## 登录恢复卡

每次首实例启动只要本机存在最新有效快照就显示恢复卡；上次是否异常退出只决定自动捕获安全模式，不决定卡片是否出现。卡片含“立即恢复”“安全恢复”“跳过”和每项勾选框。

- 等待 15 秒：卡片只隐藏，不启动、不移动任何窗口，也不删除快照。
- 跳过：只隐藏本次提示。
- 取消某项勾选：本次恢复不处理该项。
- 永久排除：把该项的可执行文件路径写入排除列表，并取消本次选择。
- 错过卡片：托盘点“聚焦恢复卡”，或从最近现场/主窗口恢复。
- 连续失败 3 次的项目默认取消，并在标题下显示“连续失败 3 次，已默认取消；可手动重新勾选重试”；用户仍可明确重新勾选进行一次受控重试。
- 恢复后会显示成功、跳过、失败、取消数量；失败或取消保留卡片和原因供重试。

若检测到上次异常退出，自动捕获在本次进程内暂停，但不会改写用户保存的捕获偏好。诊断、历史和显式恢复仍可使用；用户点击“继续捕获”后才解除该运行期门禁。

真实重启场景尚在 `NEEDS_USER_CONFIRMATION` 门禁，不能把“卡片必定在每次正常重启后出现”视为已验证承诺；手动历史恢复入口始终是兜底路径。

## 立即恢复与安全恢复

两种模式都不会关闭快照之外的程序，不结束进程，也不碰程序内部未保存内容；都会优先复用能可靠一对一匹配的普通窗口，并跳过管理员/不可访问、路径失效、歧义或连续失败达到 3 次的项目。

- 立即恢复：缺少的普通程序和仍存在的资源管理器目录可以启动，然后尽力恢复窗口位置。
- 安全恢复：仍可复用可靠匹配的现有窗口，也可打开仍存在的资源管理器目录；不会启动缺少的普通应用程序。

恢复单项默认等待最多 30 秒，同次不自动重试。单项失败不会阻止其他项；取消后停止后续动作，但不会关闭或回滚已经恢复的窗口。

## 诊断

主窗口“诊断”页显示数据库健康状态。点“预览诊断内容”会读取白名单日志的稳定快照，先删除 `commandLine`、`token`、`password`、`clipboard` 字段，将标题替换为“[已脱敏]”，并把用户目录前缀替换为 `%USERPROFILE%`。请逐行确认仍可能敏感的程序路径、目录结构和消息，再决定是否分享。

底层已经具备将同一份预览快照写入 ZIP 的能力，但 **0.1.0 当前界面没有“导出 ZIP”按钮**，也不会自动上传。人工清单要求的诊断 bundle id 因此仍为发布门禁，不能把预览当作已经导出。

## 卸载：保留还是删除

在 Windows“应用和功能/程序和功能”卸载 DeskButler。交互卸载只询问一次：“是否同时删除 DeskButler 的设置、快照和日志？”

- 选择“否”：删除程序、开始菜单入口、卸载项和 DeskButler 自己的登录启动值，保留整个 `%LOCALAPPDATA%\DeskButler`，包括常驻设置和 `resident-launch-session.json`，以后重装可继续使用。
- 选择“是”：在精确路径安全检查通过后，删除整个 `%LOCALAPPDATA%\DeskButler` 数据根，包括设置、常驻登录会话、快照、日志和故障证据。
- 静默卸载：默认保留；只有精确参数 `/DELETEUSERDATA=1` 才请求删除。

卸载只请求 DeskButler 自身自然退出，绝不终止常驻列表中的第三方应用，也不修改它们的 Run 值、计划任务或服务。

当前真实账户已有数据，因此“删除全部数据”的完整实机链尚未执行，只在静态安全契约和只读门禁中验证。不要为了测试手动删除真实数据目录。

## 做不到的事

DeskButler 不保证恢复浏览器标签页，不恢复未保存文档、IDE 工程状态、终端命令或进程内存；不记录完整命令行、屏幕、键盘、鼠标、剪贴板或文档内容；不提供第三方进程守护、崩溃重启、远程指令、云同步、AI、语音或待机形象动画。
