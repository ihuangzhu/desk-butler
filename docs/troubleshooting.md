# 故障排除

## 找不到主窗口

先查看任务栏通知区域（包括“显示隐藏的图标”），双击 DeskButler 图标，或右键选择“打开管家”。若托盘仍有图标，不要重复启动多个副本；单实例保护会让第二进程退出。

快速用户切换后的另一个 Windows 会话拥有独立会话边界。请回到最初会话检查；首版不合并不同会话的托盘实例或现场。

## 常驻应用漏检或候选没有出现

常驻发现不是后台自动动作。先让目标应用保持运行并缩到托盘，再从托盘点“保存当前现场”或在首页点“立即保存现场”；也可以打开“设置”页点“查找常驻应用”。发现面板在首页，低可信候选默认不勾选，主入口不明确时还会提示选择 `.exe`。若仍没有候选，确认应用不是管理员权限进程、安装器、helper/updater，且当前用户能读取它的可执行文件；DeskButler 不会为绕过权限而提权。

## 候选把 helper 当成主程序

在首页“发现的常驻应用”中取消该候选，或点“浏览修正”选择产品真正的主程序 `.exe` 后再确认。已经保存错误入口时，打开“设置”页，在对应条目点“替换路径”；如果无法确定产品归属，先点“删除”，让正确主程序保持运行后重新点“查找常驻应用”。不要把 updater、crash reporter 或虚拟机辅助工具加入列表。

## 应用更新后路径失效

打开“设置”页查看条目的路径状态。若显示“启动路径不存在”或“启动路径无法访问”，点“替换路径”选择更新后的主程序；发现区若显示“发现可能的新路径”，核对旧、新路径后手动勾选并确认，DeskButler 不会静默替换。修改会立即保存，但自动启动从下次 Windows 登录生效；本次登录需要时可点“立即启动常驻应用”。

## 常驻应用权限不足

DeskButler 以普通用户权限运行。若条目显示无法访问，或发现阶段漏掉管理员进程，请不要以管理员身份启动 DeskButler；在“设置”页点“替换路径”，选择当前用户可读取、位于本地固定磁盘且不在 Windows 受保护目录中的普通 `.exe`。无法核实进程状态时 DeskButler 会跳过启动，不会冒险创建重复实例。

## “立即启动”出现重复实例

先用应用自己的退出入口关闭多余实例，不要按名称强制结束进程。随后在“设置”页删除错误或重复条目，只保留一个代表性产品进程运行，点“查找常驻应用”并确认正确主程序；这样会重新建立用于去重的 `KnownProcessPaths`。再次点“立即启动常驻应用”，已运行产品应被跳过。若仍重复，保留诊断预览并记录两个实例的完整路径供排查，不要直接编辑 `settings.json`。

## 常驻登录会话记录损坏

`resident-launch-session.json` 损坏时，DeskButler 会把它保留为 `resident-launch-session.corrupt-*.json`，为当前登录写入已完成空计划并停止本次自动启动；证据无法保全时则保持原文件不变并同样停止。打开“设置”页核对常驻列表和路径，确需当前登录启动时点“立即启动常驻应用”；下一次 Windows 登录会建立新批次。不要删除或修改损坏证据，先在“诊断”页预览并记录状态。

## 登录后没有恢复卡

卡片不是自动恢复器。每次首实例启动只要存在最新有效快照就尝试显示，并在 15 秒后隐藏。请从托盘“最近现场”“聚焦恢复卡”或主窗口“现场”页手动调用。若恢复出现失败或取消，卡片会保留原因和重试入口。正常重启链尚未完成真实验收，不要把缺卡等同于快照丢失。

## 某个窗口没有保存或恢复

常见原因：窗口不是普通可见主窗口、无法解析可执行路径、属于系统/临时/安装器/DeskButler、自身被永久排除，或是管理员/不可访问窗口。DeskButler 普通权限运行，不会提权操作管理员窗口。

同一 exe 的多个相似窗口、标题变化或身份冲突可能形成歧义，系统会跳过而不是猜测。连续失败达到 3 次的项目默认跳过；一次恢复中的单项失败不影响其他项。

Explorer 目录必须仍然存在且是本地绝对路径。浏览器 tab、IDE 项目、终端命令、文档正文和未保存内容无法恢复。

## 窗口跑到错误显示器

若保存时的显示器已拔除或设备名改变，DeskButler 会回退到主显示器并限制在工作区；不同 DPI 会按保存与目标 DPI 比例缩放。若仍不可见，请先用 Windows 的窗口移动快捷键把窗口移回，再保留诊断预览。当前 Win10 受控测试覆盖负坐标和 150%/200% 缩放，Windows 11 仍待验证。

## `run.lock` 或启动异常

`%LOCALAPPDATA%\DeskButler\run.lock` 是运行身份标记，含随机 token、PID 和 UTC 时间。正常退出会删除；进程崩溃、强制结束或系统来不及清理时会保留，用于下一次识别非正常运行。不要在 DeskButler 正运行时删除或替换它。若应用已完全退出而 marker 仍在，重新启动会持有既有 marker 并把本次视为上次未正常结束；成功受控退出后应清除。

检测到残留 marker 时，DeskButler 进入运行期安全模式并暂停自动快照写入；这不会改写 `CaptureEnabled`。可先查看历史和诊断或显式恢复，再从首页或托盘点击“继续捕获”。

错误的数据库恢复 marker 会被拒绝，不会盲目删除数据库。`database-recovery.marker.json` 与 `diagnostics\database.corrupt-*` 应一起保留供排查。

## 数据库健康警告

诊断页若显示“数据库故障现场已备份，DeskButler 已创建新的本地数据库”，说明主库/WAL/SHM 已复制到 `%LOCALAPPDATA%\DeskButler\diagnostics\database.corrupt-*`，旧证据仍在，新库已建立。若提示恢复未完成，请不要删 marker 或备份目录；先复制整个 DeskButler 数据目录到安全位置，再由开发人员分析。

设置 JSON 损坏时会保留为 `settings.corrupt-*.json` 并加载默认设置；这可能让捕获和登录启动回到默认启用。

## 日志多大、在哪里

日志位于 `%LOCALAPPDATA%\DeskButler\diagnostics\logs`。活动文件 `deskbutler.jsonl` 单文件默认约 1 MiB，最多两个编号归档，总量默认约 3 MiB，允许当前单条记录作为唯一超限余量。`deskbutler.writer.lock` 只在运行期间持有并用删除即关闭语义清理。

## 分享诊断前怎么检查

1. 打开主窗口“诊断”。
2. 点“预览诊断内容”。
3. 检查每个白名单文件名、字节数和文本。标题会显示为 `[已脱敏]`，用户目录前缀显示为 `%USERPROFILE%`。
4. 仍要特别检查消息、exe 路径、Explorer 目录结构、客户/项目名称。
5. 当前 UI 没有导出 ZIP 按钮，也不会上传；不要把整个 `%LOCALAPPDATA%\DeskButler` 或数据库直接发给别人。

## 卸载或升级提示无法安全退出

先从托盘选择“退出”，等待图标消失，再重试。安装器只通过当前用户/会话的固定维护管道请求自然退出，不会按名称强杀进程；20 秒内无法取得单实例所有权时会中止，以免删除或覆盖仍在使用的文件。

卸载要删除数据时，优先使用交互询问。静默卸载默认保留整个 `%LOCALAPPDATA%\DeskButler`，包括常驻设置和登录会话；只有 `/DELETEUSERDATA=1` 才请求删除整个精确数据根，而且仍需 LocalAppData 路径与重解析点安全检查。卸载不会终止任何第三方应用，也不修改它们的 Run 值、计划任务或服务。不要手动用递归删除命令测试真实数据。
