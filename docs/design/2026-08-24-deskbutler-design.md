# DeskButler 首版设计规格

## 1. 文档目的

本文定义 DeskButler 首版的产品范围、系统边界、核心行为、数据模型、安全约束、异常处理、安装卸载与验收标准。首版只建设本地管家基础平台和 A 级工作现场恢复模块，不实现 AI、远程控制、待机形象、动画、语音或 B 级开发者增强恢复。

DeskButler 是一个全新的独立 Windows 桌面应用，项目目录位于 `D:\Projects\Php\client_dev\WebService\Html\DeskButler`。它与当前目录中的既有 PHP Web 服务不产生运行时依赖。

DeskButler 项目目录必须初始化为独立 Git 仓库，仓库元数据位于 `DeskButler\.git`。DeskButler 的源码、文档、测试和发布配置只允许提交到该独立仓库，禁止提交到外层 `client_dev` 仓库。在用户提供并确认私有远程仓库地址前，不配置远程地址，也不执行任何推送。

## 2. 产品目标

DeskButler 的长期定位是可安装、可分发、可扩展的本地电脑管家。首个功能模块用于降低 Windows 重启后重新打开程序、目录和排列窗口的重复劳动。

首版成功标准如下：

1. 管家可在 Windows 10/11 x64 上安装、登录自启动、托盘常驻并干净卸载。
2. 管家可低干扰地记录普通可见程序、资源管理器目录、窗口位置、窗口大小和显示器归属。
3. 管家保留最近 3 次有效现场快照，并能在登录后或主界面中由用户手动恢复。
4. 恢复过程不关闭当前程序、不结束进程、不覆盖未保存内容，并尽量避免重复启动。
5. 单个项目失败不影响其他项目，所有失败均可诊断、可跳过且不会无限重试。
6. 核心模块在断网、无账号和无云端服务的情况下完整工作。

## 3. 非目标

首版明确不包含：

- 休眠或进程内存恢复；
- 浏览器标签页、IDE 项目、文档内容或终端命令恢复；
- 完整命令行参数记录；
- 键盘输入、鼠标轨迹、剪贴板内容或屏幕画面记录；
- 自动关闭当前程序以匹配旧快照；
- 管理员程序的提权控制或安全边界绕过；
- AI 对话、自然语言指令、语音交互；
- 待机形象、动画角色或个性化人格；
- 手机网页、远程指令或云端同步；
- 固定工作区模板编辑器；
- Windows ARM64、macOS 或 Linux 支持；
- 自动更新服务。

## 4. 技术基线

首版采用 C#、.NET 10、WPF 和隔离的 Win32 系统适配层。发布产物采用 Windows x64 自包含方式，使目标电脑无需预装 .NET 运行时。

技术结构遵循以下约束：

- WPF 只处理托盘、提示卡片、主窗口和设置界面，不直接调用 Win32 API。
- 应用层统一承载模块生命周期、命令分发、事件通知、后台调度、权限策略和通知服务。
- 工作现场恢复作为首个独立模块实现，可单独启停。
- Windows 系统调用集中在适配层，通过接口向上提供窗口、进程、显示器、资源管理器和会话事件能力。
- 快照、恢复记录和诊断事件保存到 SQLite；用户设置保存为 JSON。
- 所有未来敏感配置必须进入 Windows 凭据存储或使用 Windows 数据保护机制，不得明文写入普通配置文件。

解决方案采用以下项目边界：

- `DeskButler.Desktop`：WPF、托盘和用户交互；
- `DeskButler.Application`：命令、事件、调度、权限和模块宿主；
- `DeskButler.Core`：领域模型、模块契约和平台无关规则；
- `DeskButler.Modules.WorkspaceRecovery`：捕获、快照、恢复规划和恢复执行；
- `DeskButler.Infrastructure.Windows`：Win32、进程、资源管理器、显示器及系统会话适配；
- `DeskButler.Persistence`：SQLite、JSON、迁移和原子写入；
- 对应的单元测试和 Windows 集成测试项目。

## 5. 管家基础平台

### 5.1 运行形态

DeskButler 是当前用户会话中的单实例托盘应用。平时不显示完整主窗口。托盘菜单至少提供：

- 保存当前现场；
- 查看和恢复最近现场；
- 暂停或继续记录；
- 打开管家；
- 退出管家。

默认启用登录自启动，用户可以在设置中关闭。自启动使用当前用户级机制，不安装 Windows 服务，不要求管理员权限。

### 5.2 模块系统

每个功能模块必须声明：

- 唯一模块标识；
- 显示名称和版本；
- 是否默认启用；
- 所需平台能力；
- 可调用命令；
- 可发布和订阅的事件；
- 用户可见设置；
- 诊断信息提供方式。

首版模块可在编译时注册，不实现第三方动态插件加载。这样保留清晰边界，同时避免首版引入程序集信任、版本兼容和插件安全问题。

### 5.3 命令与事件

界面操作必须通过统一命令总线调用业务能力。模块状态变化通过事件总线发布。首版不得为了未来 AI 或远程控制创建空功能，但命令不得与具体按钮、窗口或页面绑定。

这一边界确保未来 AI、远程控制或自动化入口可以调用同一套受控命令，而不绕过权限与业务校验。

## 6. 工作现场捕获

### 6.1 捕获范围

默认捕获满足以下条件的顶层窗口：

- 属于当前登录用户；
- 具有正常可见主窗口；
- 能解析到可执行文件路径；
- 不属于系统界面、临时弹窗、安装程序、管家自身或用户排除项。

每个捕获项目最多保存：

- 程序可执行文件路径；
- 用于匹配的最小窗口身份信息；
- 窗口位置和大小；
- 窗口状态，例如普通、最大化或最小化；
- 显示器稳定标识及捕获时的工作区坐标；
- 资源管理器窗口对应的目录路径；
- 捕获时间和捕获来源。

首版不保存完整进程命令行。窗口标题只保存恢复匹配所需内容；诊断导出时应进一步脱敏或允许用户预览。

### 6.2 排除规则

内置排除至少覆盖：

- Windows 桌面、任务栏、开始菜单、锁屏和安全界面；
- 后台服务和无可见窗口进程；
- DeskButler 自身窗口；
- 临时对话框、提示框和安装器；
- 无法解析安全启动路径的窗口；
- 用户永久排除的程序。

用户可以从快照详情中取消单个项目，或将程序加入永久排除列表。永久排除以稳定的程序身份保存，不能只依赖变化频繁的窗口标题。

### 6.3 保存时机

捕获采用事件驱动和防抖合并：

1. 程序或窗口发生有意义的变化时标记现场为待保存；
2. 短时间内的连续变化合并为一次写入；
3. 系统空闲期间写入自动检查点；
4. 收到正常注销、重启或应用退出通知时，尽力写入最终检查点；
5. 用户可以随时手动保存。

系统关机通知不能作为唯一保存来源，因为系统异常退出或更新流程可能不给应用足够时间。窗口变化停止 10 秒后写入合并快照；如果变化持续发生，现场处于待保存状态满 60 秒时强制写入检查点。性能测试可以延长这两个时间，但不得缩短到造成连续高频写盘。

### 6.4 快照一致性与保留

每次快照先完整写入并验证，再标记为有效。只有新快照生效后才删除最旧快照。自动快照最多保留最近 3 份有效记录。

快照必须包含数据格式版本。应用升级时通过显式迁移读取旧版本；无法迁移的记录保留原始数据并标记不可恢复，不得静默删除。

## 7. 工作现场恢复

### 7.1 恢复入口

登录启动后，如果存在有效快照，右下角显示恢复卡片。卡片提供：

- 立即恢复；
- 安全恢复；
- 跳过；
- 查看详情。

卡片 15 秒后自动收起，但不会自动执行恢复，也不会删除快照。用户可以随时从托盘或主界面选择最近 3 次中的任意一份快照手动恢复。

### 7.2 恢复原则

首版恢复是“补充并整理”，不是“清空并重建”：

- 不关闭快照之外的当前程序；
- 不结束任何进程；
- 不覆盖或操作程序内部未保存内容；
- 优先复用能够可靠匹配的现有窗口；
- 只启动缺少且具备安全启动路径的程序；
- 宁可少恢复，也不重复乱开；
- 无法可靠识别的现有窗口保持原样；
- 单个项目失败不得中断其他项目。

### 7.3 恢复步骤

恢复执行器按以下步骤工作：

1. 读取并验证快照；
2. 获取当前程序、窗口和显示器状态；
3. 生成恢复计划，将项目分为复用、启动、跳过和不可恢复；
4. 向用户展示可取消勾选的计划；
5. 分批启动缺少的程序和资源管理器目录；
6. 在限定时间内匹配新窗口；
7. 将可靠匹配的窗口恢复到有效屏幕范围；
8. 输出成功、跳过和失败结果；
9. 保存恢复记录和必要诊断信息。

恢复任务必须支持取消。取消后停止后续启动和移动操作，但不撤销已经启动的程序，也不关闭任何窗口。

### 7.4 窗口与程序匹配

程序匹配优先使用稳定属性组合，例如规范化可执行文件路径、进程身份、窗口类和经过约束的标题特征。不得仅使用进程号，因为重启后进程号会变化；不得仅使用完整标题，因为文档名和页面名可能变化。

首版对多实例程序采取保守策略。只有现有实例与快照项目能够形成可靠的一对一关系时才调整位置。存在歧义时，项目标记为部分恢复或跳过，并交给用户处理。

### 7.5 多显示器与 DPI

保存窗口时同时记录显示器标识、工作区坐标和相对位置。恢复时：

- 原显示器存在时，优先恢复到原显示器；
- 原显示器不存在时，迁移到当前主显示器的可见工作区；
- 坐标必须按当前 DPI 和工作区重新约束；
- 不允许窗口标题栏完全落到可见区域之外；
- 显示器重新接入不会自动搬动已经恢复的窗口，除非用户再次执行恢复。

### 7.6 安全恢复

安全恢复用于上次恢复失败、管家异常退出或用户主动选择的场景。安全恢复默认只处理：

- 有效资源管理器目录；
- 明确允许且最近未连续失败的普通程序；
- 能够可靠匹配的现有窗口位置。

管理员程序、连续失败程序、启动路径异常程序和身份歧义项目全部跳过。

## 8. 权限与安全

DeskButler 默认以当前用户普通权限运行。它不得自动请求管理员权限，也不得通过辅助服务、注入、模拟凭据或其他方式控制高权限程序。

遇到管理员窗口时，可以读取系统允许公开的信息，但如果无法移动、识别或启动，应记录为权限不足并跳过。界面需向用户说明原因。

首版不得提供任意命令执行入口。所有可执行动作必须来自编译时注册、具备明确参数和风险说明的命令。

本地数据不上传。诊断包必须由用户主动导出，并在导出前展示包含的数据类别。路径和窗口标题可能包含个人信息，导出时需要提供脱敏选项。

## 9. 异常处理与诊断

### 9.1 恢复失败

每个恢复项目具有独立超时、取消和结果状态。单个程序默认最多等待 30 秒完成启动和主窗口匹配，超时后标记失败并继续下一项。项目失败后不得在同一次恢复中自动重试；连续 3 次恢复失败后，下一次恢复默认不勾选该项目并提示用户处理。

### 9.2 快照损坏

快照读取失败时按时间倒序尝试上一份有效快照。损坏记录保留用于诊断，但不得继续参与自动推荐。数据库整体无法读取时，先备份原文件，再创建新数据库；不得直接覆盖唯一故障现场。

### 9.3 管家崩溃

记录未处理异常和最近操作阶段。下次启动检测到非正常退出时进入安全模式：暂停自动捕获写入，允许查看诊断、验证数据并由用户决定是否恢复正常运行。

### 9.4 日志

日志按大小或日期轮换，并设置总量上限。默认日志不得记录文档内容、完整命令行、键盘输入、访问令牌或凭据。日志级别和诊断导出范围必须可说明。

## 10. 界面与交互

首版采用托盘优先的极简形态。主窗口至少包含：

- 首页：运行状态、最近现场和最近恢复结果；
- 现场：最近 3 次快照及其项目详情；
- 模块：工作现场恢复的启停状态，并为未来模块保留一致呈现方式；
- 设置：开机启动、捕获暂停、排除列表、通知和数据管理；
- 诊断：健康状态、失败项目、日志和诊断包导出。

首版界面使用简体中文。界面文本应集中管理，为未来多语言保留资源化能力，但首版不要求提供其他语言。

## 11. 安装、升级与卸载

### 11.1 安装

- 使用标准 Windows 安装包；
- 首选当前用户安装，避免管理员权限；
- 默认注册当前用户登录自启动；
- 创建正常的开始菜单和卸载入口；
- 安装程序文件与用户数据分离。

### 11.2 升级

首版不实现后台自动更新。新版安装包应支持覆盖升级，并保留设置、快照、排除列表和恢复记录。数据库迁移失败时终止升级或回滚应用数据迁移，不允许半迁移状态继续运行。

### 11.3 卸载

卸载必须删除程序文件、开始菜单项、登录自启动项和系统集成。用户可选择：

- 保留设置、快照和日志，供以后重装；
- 删除全部 DeskButler 用户数据。

选择彻底删除后，不得残留 DeskButler 创建的计划任务、启动项、缓存或日志。卸载程序不得删除不属于 DeskButler 的共享组件或用户文件。

## 12. 源码仓库隔离

- 项目根目录为 `D:\Projects\Php\client_dev\WebService\Html\DeskButler`；
- 项目根目录内建立独立 `.git`，不得复用外层仓库；
- 所有 DeskButler 提交必须在项目根目录执行，并在提交前核对 `git rev-parse --show-toplevel` 的结果正好是 DeskButler 根目录；
- 不得把 DeskButler 文件加入外层 `client_dev` 仓库的暂存区；
- 未经用户明确提供和确认，不添加任何远程仓库；
- 只允许连接用户指定的私有远程仓库，禁止推送到公开仓库；
- 密钥、令牌、签名证书、用户快照、诊断日志和本机构建产物必须由 `.gitignore` 排除；
- 首次提交前必须检查暂存文件，确认不存在凭据、个人数据或外层项目文件。

## 13. 测试与验收

### 13.1 自动化测试

核心规则通过平台接口模拟测试，至少覆盖：

- 捕获过滤和排除规则；
- 防抖合并和三份快照保留；
- 快照原子写入和版本迁移；
- 恢复计划分类；
- 现有窗口复用与重复启动抑制；
- 超时、取消、部分失败和连续失败降级；
- 显示器缺失及坐标回收；
- 日志脱敏和轮换；
- 数据损坏回退。

### 13.2 Windows 集成测试

真实系统测试至少覆盖：

- Windows 10 x64 和 Windows 11 x64；
- 单显示器、多显示器、不同缩放比例和显示器断开；
- 资源管理器、记事本及若干普通单实例和多实例程序；
- 程序已运行、未运行、路径失效、启动超时和权限不足；
- 正常退出、注销、重启通知和进程异常终止；
- 安装、覆盖升级、卸载保留数据和彻底卸载；
- 长时间后台运行下 CPU、内存、句柄和存储是否持续增长。

首版不以特定浏览器、IDE或终端内部状态恢复作为验收条件。

### 13.3 发布门槛

发布候选版本必须满足：

- 所有自动化测试通过；
- Windows 10 和 Windows 11 基线测试通过；
- 不存在无限恢复、崩溃循环或自动关闭用户程序的行为；
- 三份快照保留和损坏回退可验证；
- 安装、升级、卸载和数据选择行为可验证；
- 后台资源使用无持续增长趋势；
- 已知兼容性限制写入用户文档。

## 14. 未来路线图与预留边界

以下能力不属于首版，但架构必须允许后续独立增加：

1. B 级开发者增强恢复：浏览器会话、IDE 项目、终端配置和工作目录；
2. AI 管家：文字对话、意图识别、本地工具调用、权限确认和可替换 AI 提供方；
3. 形象交互：待机、聆听、思考、说话、工作、成功、警告、错误和休息状态；
4. 可替换形象渲染器：轻量动画、WebView2、Skia、Live2D 或其他渲染方式；
5. 语音交互：语音识别、语音合成和实时对话；
6. 手机网页远程控制：设备配对、加密通信、权限分级和审计；
7. 其他管家模块：提醒、文件整理、启动项分析和系统巡检；
8. 用户自选目录同步或其他可选同步方式。

未来入口必须继续使用统一命令、事件和权限边界，不能直接调用底层系统适配层。远程控制和 AI 不得获得任意命令执行权限。

## 15. 已确认的产品决策

- 产品是全新的独立 Windows 应用；
- 可安装并可分发给其他用户；
- 首期完全本地，每台电脑独立配置；
- 支持 Windows 10/11 x64；
- 标准安装包优先，并要求干净卸载；
- 托盘优先，不以完整控制台作为日常入口；
- 首版只实现基础平台和 A 级工作现场恢复；
- 登录后只提示，不自动恢复；
- 错过提示后可手动恢复；
- 保留最近 3 次有效快照；
- 默认记录普通可见程序并支持永久排除；
- 恢复不关闭当前程序；
- 优先复用现有窗口，宁可少开也不重复乱开；
- 首版不保存完整命令行；
- AI、远程、形象、动画、语音和 B 级恢复以后分阶段实现；
- 开发代号和项目目录名为 DeskButler。
- DeskButler 使用项目目录内的独立私有 Git 仓库，不向外层仓库或公开远程仓库提交。
